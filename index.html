つくったもの

毎月くり返していた事務作業を、
自作のアプリに置き換えました。

請求書の作成、領収書の発行、イベントの収支管理、クレジットカードの支出把握。 いずれも毎月発生し、そのたびに時間を取られていた業務です。 ここに掲載しているのは、実際の業務で使っているものを、 中身だけ架空のデータに入れ替えたデモ版です。 登録もログインも不要で、開いてすぐ操作できます。

請求書の作成

毎月の作成を、選択と入力だけに

課題
毎月、前月の請求書ファイルを複製し、日付と金額を書き換えていました。源泉徴収の計算を電卓で行っていたため、記載ミスも起きていました。
解決策
取引先を一度登録しておけば、あとは取引先を選び、金額を入力するだけです。消費税と源泉徴収の差し引きまで自動で計算し、そのままPDFとして書き出します。発行した請求書は一覧に残るため、入金の有無も後から確認できます。
  • PDFで書き出し
  • 消費税と源泉徴収を自動計算
  • 入金状況の管理
  • スマホ対応
使用技術

HTML / CSS / JavaScript のみ。PDF生成に jsPDF、保存はブラウザの localStorage。ビルド工程なしの静的ファイル1枚で完結。

領収書の発行

数十枚を貼り付け一括で作成

課題
入金一覧を見ながら、領収書を1枚ずつ作成していました。月末に数十枚たまると、それだけで半日近く取られます。
解決策
入金一覧をコピーして貼り付けるだけで、必要な枚数をまとめて作成します。A4用紙に2枚ずつ配置した形で出力されるため、印刷して切り分けるだけで済みます。社名や但し書きは、発行元ごとに切り替えられます。
  • 貼り付けて一括作成
  • 印刷用のPDFを出力
  • 発行元ごとに切り替え
使用技術

HTML / CSS / JavaScript。画面を html2canvas で画像化し jsPDF で1つのPDFに結合。実際に稼働している版は Firebase Authentication で利用者を限定。

イベントの収支管理

複数案の比較から実績確認まで

課題
合宿の見積もりを表計算ソフトで作成していましたが、2人で同時に編集すると計算式が壊れ、どれが最新版か分からなくなっていました。
解決策
宿泊の部屋数や食事の回数を変えた案を複数作成し、どの案が黒字になるか、何人集まれば採算が合うかを並べて比較できます。採用する案を決めたら予算として確定し、開催後に実績を入力して差額を確認します。2人が同時に開いても、一方の入力がもう一方の画面にすぐ反映されます。
  • 複数の案を並べて比較
  • 損益分岐点を自動計算
  • 2人で同時に編集
  • 自動保存
使用技術

Firebase Authentication（Googleログイン）＋ Cloud Firestore ＋ Firebase Hosting。onSnapshot による購読でリアルタイム同期。アプリ本体は約3,000行。

クレジットカードの支出管理

4枚分を支払月ベースで集計

課題
カード4枚の請求メールが個別に届くうえ、締め日も引き落とし日もカード会社ごとに異なります。結果として、月にいくら使っているのかを把握できていませんでした。
解決策
受信した請求メールを自動で読み取って集計し、実際に引き落とされた月を基準にそろえてグラフ化しました。締め日がずれるカードも、引き落とし月に合わせて計上しています。用途別の内訳と、毎月定額で引き落とされているサービスの抽出も行います。
  • メールから自動集計
  • グラフで推移を比較
  • 用途別の内訳
  • 定額サービスの検出
使用技術

グラフ描画ライブラリを使わず、素の SVG を JavaScript で組み立て。メールからの抽出・集計は別途スクリプトで実行し、結果をこの画面に流し込む構成。

デモ版について

  • 掲載している社名・氏名・金額はすべて架空です。実在の個人・法人および実際の取引とは関係ありません。
  • ログインは不要です。入力した内容は外部に送信されず、ご覧の端末内にのみ保存されます。
  • 画面上部の「初期状態に戻す」で、いつでもサンプルデータの状態に戻せます。
  • 実際に稼働しているものとは別のコピーで、実データは含まれていません。
